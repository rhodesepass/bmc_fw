设备固件更新

推荐 Wi-Fi 传输 · 先在 HTTPS / localhost 页面用蓝牙连接设备，配置 Wi-Fi 后打开设备上传页。

01 / 建立 Wi-Fi 通道

接入现有 Wi-Fi，或由设备直接开启热点。BLE 负责握手，镜像经 Wi-Fi 传输；也可保留蓝牙连接直接使用下方更新功能。

尚未配置

打开设备 Wi-Fi 上传页 →

热点开启后，请在系统设置中切换 Wi-Fi。上传页由设备提供，无需再次连接蓝牙。素材通道接口已预留，当前尚未接入素材接收端。

02 / 更新内容

仅更新 BMC 时无需 U-Boot FIT。更新 D1s / CH32 时，由 BMC 正常 SPL 接收完整 U-Boot 至 RAM，再刷写更新目标。

追加同一批更新的其他目标

所有选定文件校验后才开始更新。BMC 先写备用槽并校验暂存，再更新 D1s / CH32；全部 END 确认后统一提交，不自动重启。点击启动按钮后才启动新固件。三芯片更新不是原子事务：D1s / CH32 为原地写入，中断时可能已更新部分固件。目标不能重复；仅校验模式不能追加目标。坏块可能减少实际容量。断电或会话丢失后需从头重刷；单份系统没有自动回滚。BMC 需已安装支持 RAM FIT 接收的正常 SPL；更新不依赖 NAND 中的现有内容。

03 / 设备确认

等待更新

END 确认表示单个镜像已校验；还需统一提交确认，启动后重新连接验证运行状态。BMC 的 END 不切换启动槽，统一提交时才切槽，启动按钮显式重启 BMC。U-Boot RAM 与仅校验目标的持久化进度保持为零。touch 收齐并验证 SHA256 后才烧录 CH32，回读一致后持久化进度一次变为完整大小。触控更新需要支持 touch 的 BMC 固件和 U-Boot。Wi-Fi 上传同样逐帧等待设备确认；中断后需重新开始更新。
